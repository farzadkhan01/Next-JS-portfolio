# PROJECT.md — Farzad Khan Portfolio

## 1. Project Overview

**Project Name:** Farzad Khan — Developer Portfolio

**Project Type:** Personal Brand & Professional Developer Portfolio

**Owner:** Farzad Khan

**Primary Role:** Frontend Engineer with Full-Stack JavaScript Capabilities

**Primary Objective:** Build a premium, modern, conversion-focused developer portfolio that establishes professional credibility, showcases engineering capabilities, attracts international design agencies, and generates freelance opportunities.

This is not a generic developer portfolio. It should communicate technical expertise, strong visual judgment, attention to detail, and the ability to transform designs into polished, production-ready web experiences.

---

## 2. Project Vision

Create a distinctive digital identity that positions Farzad as a capable frontend engineer who understands both design and engineering.

The experience should immediately communicate:

- Who I am.
- What I build.
- What technologies I work with.
- What problems I can solve.
- Why an agency or client should work with me.
- How someone can contact or hire me.

The website must balance visual creativity with clarity, usability, accessibility, and performance.

It should remain relevant as my skills, professional experience, and portfolio grow over the next 3–5 years.

## 5. Design Philosophy

### Primary Design Direction

A carefully balanced combination of:

- Minimalism
- Bento Grid layouts
- Editorial design
- Subtle Glassmorphism
- Premium typography
- Generous whitespace
- Sophisticated light and dark themes

The design must feel modern, confident, distinctive, and internationally competitive.

### Visual Characteristics

- Clean compositions.
- Strong visual hierarchy.
- Consistent spacing.
- Intentional use of negative space.
- Carefully selected accent colors.
- Subtle borders and shadows.
- Refined card interactions.
- Clear typography.
- High-quality project imagery.

Avoid unnecessary decoration, excessive gradients, excessive blur, generic templates, and visual clutter.

### Theme Strategy

- Light theme is the default.
- Visitors can switch between light and dark themes.
- Remember the selected theme.
- Maintain consistent design quality across both themes.
- Respect system preferences when appropriate.
- Ensure sufficient contrast in both themes.

## 7. Project Showcase Strategy

Projects are a major part of the portfolio's credibility and conversion strategy.

The owner will independently add, edit, and remove projects.

Create a centralized JavaScript data structure that supports:

- Project title.
- URL slug.
- Short description.
- Detailed overview.
- Project category.
- Technologies used.
- Cover image.
- Additional screenshots.
- Live demo URL.
- Source code URL.
- Key features.
- Challenges and solutions.
- Owner's contribution.
- Featured status.
- Display order.

Project case studies should communicate the problem, implementation, technical decisions, and outcome.

Do not fabricate project results, users, business metrics, or client information.

The website must remain functional even when only a few projects have been added.

### Technology Stack

- Next.js — App Router.
- JavaScript — no TypeScript.
- Tailwind CSS.
- GSAP.
- Motion (formerly Framer Motion).
- Lucide React.
- Vercel.

Use compatible, current stable versions and official documentation.

### Development Principles

- Component-based architecture.
- Reusable UI components.
- Centralized content data.
- Separation of concerns.
- Maintainable folder structure.

- Avoid unnecessary client-side JavaScript.

- Bento card interactions.
- Project image transitions.
- Subtle magnetic buttons where appropriate.
- Navigation transitions.
- Theme transitions.
- Page transitions.
- Refined hover interactions.

### Animation Responsibilities

**GSAP:**

- Advanced timeline animations.
- ScrollTrigger scenes.
- Complex entrance animations.
- Scroll-based storytelling.

**Motion:**

- React component transitions.
- Interactive UI elements.
- Layout animations.
- Navigation and modal interactions.

**CSS:**

- Lightweight hover states.
- Simple transitions.
- Basic visual effects.

Every animation must consider mobile performance and reduced-motion preferences.

## 12. Quality Standards

### Responsive Design

Support:

- Small mobile devices.
- Standard smartphones.
- Tablets.
- Laptops.
- Desktop displays.
- Large screens.

Mobile must be designed intentionally, not treated as a compressed desktop layout.

### Accessibility

- Semantic HTML.
- Keyboard navigation.
- Accessible buttons and links.
- Visible focus states.
- Sufficient color contrast.
- Meaningful image alt text.
- Reduced-motion support.

### Performance

- Optimized images.
- Lazy loading where appropriate.
- Efficient animations.
- Minimal unnecessary dependencies.
- Optimized fonts.
- Good Core Web Vitals.

### SEO

- Unique page metadata.
- Descriptive titles and descriptions.
- Open Graph metadata.
- Sitemap.
- Robots.txt.
- Structured data where appropriate.
- Canonical URLs.
- Search-friendly project case studies.

### Security & Reliability

- No exposed secrets.
- Safe external links.
- Secure contact form implementation.
- Input validation.
- Proper error handling.
- No unnecessary third-party scripts.
